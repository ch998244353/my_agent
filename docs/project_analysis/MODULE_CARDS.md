## 1. 通用 Agent 组合与运行内核

- **职责**：[FACT] 把 Agent 定义、运行配置、状态、模型回合、下一步决策和结果串成同一 producer，并提供 sync、async 与事件流三种消费入口。`src/agents/agent.py::Agent`、`src/agents/runner.py::Runner`、`src/agents/run_loop.py::_run_agent_loop_impl`
- **边界**：[FACT] 不选择 Chat/Coding profile；产品层可调用 `Agent.run()`、`run_async()` 或 `run_stream()`，三者不复制运行循环。`src/agents/agent.py::Agent.run`、`Agent.run_async`、`Agent.run_stream`
- **主要文件/符号**：`src/agents/agent.py::Agent`，`src/agents/runner.py::RunStream`、`SyncRunCollector`、`Runner.run_stream`、`run_async`、`run_sync`，`src/agents/run_loop.py::run_agent_loop`、`_resolve_task_binding`，`src/agents/run_state.py::RunState`，`src/agents/result.py::RunResult`
- **输入/输出**：[FACT] 输入为 task 字符串与可选 `RunConfig`；配置可完全 opt-in 地携带既有 `TaskStore/task_id` 和外部 `ContextChunk` 元组。stream 入口输出有序 `RunEvent`，async/sync 入口输出同一个 producer 的 `RunResult`。`src/agents/run_config.py::RunConfig`、`src/agents/runner.py::Runner`
- **依赖与调用者**：[FACT] Chat 与 Coding 入口均调用该模块；内核向下调用 model/tool/handoff/guardrail 模块。`src/agents/chat.py::run_chat_turn`、`src/agents/coding_cli.py::run_coding_agent_cli`、`src/agents/run_loop.py::_run_agent_loop_impl`
- **副作用/扩展点**：[FACT] 会修改 `Agent.memory`、`RunState`，可调用 lifecycle hooks；完整任务绑定会在这些业务副作用前读取一次 Store，并在结果/session 前再读取一次当前节点 revision。`src/agents/run_loop.py::_run_agent_loop_impl`、`_build_result_and_save_session`
- **相关测试**：`tests/test_runner.py`、`tests/test_run_state.py`、`tests/test_run_steps.py`、`tests/test_task_runtime.py`

## 2. 模型适配、attempt 事件与回合上下文

- **职责**：[FACT] 从 memory、repo context、session 与工具 schema 生成一次模型请求；OpenAI 原始流、同步完整响应或 legacy 决策都转换成同一组模型 attempt 事件，再由现有累加器还原 `ModelResponse`/`ToolCall`；生产回合通过唯一异步执行器发送、记录、等待、重试和显式降级。`src/agents/model_turn.py::prepare_turn_input`、`_run_model_turn_async`、`src/agents/models.py::OpenAIResponsesModel.stream_response`、`stream_model_response`、`src/agents/model_events.py::ModelEventAccumulator.finish`、`src/agents/model_retry.py::run_model_request`
- **边界**：[FACT] 回合层不决定工具执行；供应商 `ModelEvent` 不直接暴露给 `run_loop`。公共 `run_model_request()` 已有 total deadline、可选现有 token、一次同模型 non-stream fallback 和一次显式备用模型 fallback，但不支持 fallback 链、路由或 provider 切换；内部 notice mapper 只把 attempt started/retry/fallback 投影成对外 `RunEvent`。`src/agents/turn_resolution.py::process_model_turn`、`src/agents/model_retry.py::run_model_request`、`src/agents/model_turn.py::_emit_model_attempt_notice`
- **主要文件/符号**：`src/agents/model_turn.py::TurnInput`、`run_model_turn`；`src/agents/contracts.py::ModelRequest`；`src/agents/models.py::ModelAdapter`、`StreamingModelAdapter`、`OpenAIResponsesModel`、`ModelResponseError`、`classify_openai_model_error`、`classify_model_error`、`_OpenAIEventMapper`、`stream_sync_model_response`、`stream_model_response`、`run_non_stream_model_response`；`src/agents/model_events.py::ModelEvent`、`ModelEventAccumulator`；`src/agents/model_retry.py::RetryAction`、`RetryDecision`、`RetryDelayDecision`、`RetryPolicy`、`parse_retry_after`、`compute_retry_delay`、`ModelAttemptRecord`、`ModelAttemptNotice`、`ModelCancelledError`、`ModelExecution`、`ModelExecutionError`、`_await_with_limits`、`_sleep_with_cancel`、`run_model_request`
- **输入/输出**：[FACT] `TurnInput` 含消息、工具说明、模型设置；`ModelRequest` 增加 request/attempt identity；native/sync/legacy 三条适配路径都输出连续 `ModelEvent`，完整聚合结果仍是现有 `ModelResponse`。执行器输入 base request 和模型，成功输出不可变 attempts 与 response，最终失败输出最后稳定错误和全部已发生 attempt；两类 fallback 的相邻 records 使用统一 reason，并由公共事件携带目标 attempt id、from/to model 和 from/to mode。回合层只在成功后提交 response/tool calls。`src/agents/model_turn.py::TurnInput`、`src/agents/model_retry.py::run_model_request`、`src/agents/events.py::ModelFallbackEvent`
- **依赖与调用者**：[FACT] `run_model_request()` 调用统一流入口、累加器、通用错误分类和 delay 计算，并已从包根公开；CodeGraph 复核的唯一生产 caller 是 `_run_model_turn_async()`，随后结果回到 `run_model_turn()` 和 `run_loop`。`src/agents/__init__.py`、`src/agents/model_retry.py::run_model_request`、`src/agents/model_turn.py::_run_model_turn_async`
- **副作用/扩展点**：[FACT] OpenAI 原生流与一次性非流入口只在完整成功后更新 response 状态；失败保留旧状态。未知非关键 provider 事件只累计整数计数，不保存原始对象；缓冲越界只保留上限与尝试字符数，正文和半截工具参数会被释放。不同于 adapter 默认模型的请求不携带旧 `previous_response_id`，成功后将其清空，且不会修改 adapter 的默认 `model`。`run_model_request()` 只在目标 fallback attempt 通过取消/deadline 检查后发布 fallback notice；同一组 attempts 进入 state/result/snapshot v4，model span 从相邻 records 推导一组定位字段，不另建 metrics 状态。已经启动的任意同步线程不能被 asyncio 强杀，迟到结果只会被忽略。`src/agents/model_retry.py::run_model_request`、`src/agents/model_turn.py::_record_model_execution_span`、`src/agents/run_state.py::_model_attempt_to_state`
- **相关测试**：`tests/test_models.py`、`tests/test_model_events.py`、`tests/test_model_stream_adapter.py`、`tests/test_model_retry.py`、`tests/test_public_api.py`、`tests/test_tool_schema.py`

## 8. 运行事件值、序列化、reducer 与旧记录适配

- **职责**：[FACT] 定义不可变运行事件、转为 JSON-compatible 字典，并由单 run reducer 注入连续序号和 UTC 时间、锁定首个终态。`src/agents/events.py::RunEvent`、`event_to_dict`、`RunEventReducer`
- **事件范围**：[FACT] 当前具体事件覆盖 run/turn 生命周期、model、model attempt started/retry/fallback、tool、approval、steer 与非终态 run error；run 结束明确区分 completed、stopped、cancelled、failed。`src/agents/events.py::RunEventType`、`ModelAttemptStartedEvent`、`ModelRetryScheduledEvent`、`ModelFallbackEvent`、`TerminalRunEvent`
- **边界**：[FACT] 事件已通过公共 `RunStream` 输出，但仍不保存事件历史、不写文件、不反序列化；现有 `RunItem`、trajectory 和 tracing 继续保留。`src/agents/runner.py::RunStream`、`src/agents/events.py::RunEventReducer`
- **输入/输出**：[FACT] `event_to_dict()` 输入 `RunEvent`，输出含稳定 `event_type`、公共字段和具体载荷的字典；UTC 时间以 `Z` 结尾。`src/agents/events.py::event_to_dict`
- **状态**：[FACT] 每个 `RunEventReducer` 只保存自己的下一个 sequence 和首个 terminal；构造事件失败不消耗 sequence，terminal 后继续 emit 会抛 `RunAlreadyFinishedError`。`src/agents/events.py::RunEventReducer.emit`
- **异常**：[FACT] `RunAlreadyFinishedError` 携带 run id 与终态 sequence；`RunCancelledError` 携带 run id 与取消原因，并由 token 的合作取消检查抛出。`src/agents/events.py::RunAlreadyFinishedError`、`RunCancelledError`、`src/agents/run_control.py::CancellationToken.raise_if_cancelled`
- **兼容**：[FACT] `emit_run_item_event()` 只把语义明确的现有 `RunItem` 转成事件；未覆盖的 guardrail、handoff、verification 返回 `None`，不会产生通用兜底事件。`src/agents/event_compat.py::emit_run_item_event`
- **依赖方向**：[FACT] `event_compat` 依赖 `contracts` 与 `events`；纯 `events` 模块不反向依赖 `RunItem`。`src/agents/event_compat.py`、`src/agents/events.py`
- **接入状态**：[FACT] `agents.__init__` 公开 `RunStream`、事件类型/错误/转换函数和三个运行控制值；producer、channel、runtime、bridge、attempt notice mapper 与 metrics snapshot 均保持内部。`src/agents/__init__.py::__all__`、`src/agents/run_control.py::_run_agent_loop_with_events`、`src/agents/model_turn.py::_emit_model_attempt_notice`
- **相关测试**：`tests/test_events.py`、`tests/test_event_compat.py`

## 9. 单 run 取消、steer 与有界事件运输

- **职责**：[FACT] 为单次 run 提供幂等取消信号、controller 生命周期、steer FIFO、有界异步事件通道和最小 runtime bundle。`src/agents/run_control.py::CancellationToken`、`RunController`、`_EventChannel`、`_RunRuntime`
- **公共边界**：[FACT] SDK 顶层公开 `RunStream`、`CancellationToken`、`RunController`、`SteerMessage` 和事件族；channel、runtime、bridge、factory、wakeup 与 metrics snapshot 保持内部。`src/agents/__init__.py::__all__`、`src/agents/run_control.py`
- **输入/输出**：[FACT] controller 接受 cancel/steer；runtime `emit()` 让 reducer 编号后 await channel，并在 terminal 发送尝试后 finish controller。`src/agents/run_control.py::RunController.cancel`、`steer`、`_RunRuntime.emit`
- **背压与清理**：[FACT] `_EventChannel` 使用 `asyncio.Queue(maxsize)`；满队列同时等待空位和 consumer-closed，close 用内部 sentinel，所有临时 task 都 cancel 后 await。`src/agents/run_control.py::_EventChannel._send_or_consumer_closed`、`close`、`__aiter__`
- **取消上限**：[FACT] runtime 只在 token 已取消后等待配置宽限期，超时调用 `Task.cancel()` 并 gather；它不保证终止吞掉 `CancelledError` 的 coroutine 或已运行的同步工具线程。`src/agents/run_control.py::_RunRuntime.shutdown_after_cancel`、`src/agents/tool_runtime.py::run_with_timeout`
- **配置**：[FACT] `event_queue_size` 默认 100 且至少 1；`cancellation_grace_period` 默认 0.1 秒且必须有限、非负。`src/agents/run_config.py::RunConfig.__post_init__`
- **线程/event-loop 边界**：[FACT] token/controller 用 `threading.Event/Lock`；同步 loop 在 worker thread 执行，`_LoopEventBridge` 用 `run_coroutine_threadsafe()` 把事件送回所属 asyncio loop。`src/agents/run_control.py::_LoopEventBridge`、`_run_agent_loop_with_events`
- **取消与终态**：[FACT] loop 在模型输入、模型返回、工具请求、handler 前后检查 token；取消单独抛 `RunCancelledError`，不记成模型/工具错误。producer 最终只发布 completed、stopped、cancelled、failed 之一；失败前紧邻 `RunErrorEvent`。`src/agents/run_loop.py::_run_agent_loop_impl`、`src/agents/run_control.py::_run_agent_loop_with_events`
- **steer 边界**：[FACT] controller 同步入队，worker 在 turn 间安全边界按 FIFO drain，先发布 accepted，再写 user messages，最后发布 applied；取消或 limit 先发生时不应用。`src/agents/run_control.py::RunController.steer`、`src/agents/run_loop.py::_apply_pending_steers`
- **指标**：[FACT] runtime 以 `perf_counter()` 记录成功入队的最长等待和 cancel-to-terminal，channel 记录最大深度，结果写入 `event_stream` span。`src/agents/run_control.py::_RunRuntime._deliver`、`metrics_snapshot`、`src/agents/runner.py::RunStream._produce`
- **接入状态**：[FACT] producer 已由 `Runner.run_stream/run_async/run_sync` 与 `Agent` 对应入口公开；CLI/session 仍使用同步返回，不直接消费事件。`src/agents/runner.py::Runner`、`src/agents/agent.py::Agent`
- **相关测试**：`tests/test_run_control.py`、`tests/test_event_channel.py`、`tests/test_run_event_bridge.py`、`tests/test_public_api.py`

## 10. Task Graph、事件 journal 与重放

- **职责**：[FACT] 保存进程内任务节点、六种状态、parent 创建树、dependency DAG、可运行查询和级联变化；为每个实际节点变化留下 `TaskEvent`，并从有序事件重建等价 Store。`src/agents/task_state.py::TaskStore`、`src/agents/task_events.py::replay_task_events`
- **主要文件/符号**：`src/agents/task_state.py::TaskStatus`、`TaskSpec`、`TaskNode`、`TaskEvent`、`TaskStore`、`_reduce_task_event`；`src/agents/task_events.py::task_node_to_dict`、`task_event_to_dict`、`replay_task_events`

- **最终状态**：[FACT] VerificationResult 恰有一条、命令与冻结值相同且 passed 时，final 转 COMPLETED 并保存计划 completed；Store 在同一事务把 Conversation.mode 改回 default。返回失败时保存固定 verification_failed；执行器异常、返回形状异常或 manifest 漂移保存固定 verification_unavailable；两者都让 final 保持 RUNNING、计划 paused，且不产生 FAILED TaskEvent。`src/agents/chat_backend/planning_service.py::PlanningService._run_final_verification`、`_safe_run_error`、`src/agents/chat_backend/planning_store.py::PlanStore.save_execution`
- **审批暂停与消息边界**：[FACT] 草案继续用 `PostgresSession + CommitOnSuccessSession` 保存可读 question/Markdown；普通步骤不从 RunEvent 拼回答，直接读取 `RunResult.final_output`。待审批结果经 `RunResult.to_state()` 和现有 v4 codec 保存；同轮安全工具从最后模型响应恢复并重新经过当前审批规则，仍需审批的调用不会被自动执行。安全快照只用现有审批摘要投影工具名、调用 id、摘要和原因，不公开完整 patch、环境变量值、私有模型状态或 RunState。`src/agents/chat_backend/planning_service.py::PlanningService.draft`、`_run_current_step`、`_snapshot_from_run`、`src/agents/run_state.py::_paused_turn_tool_calls`、`src/agents/run_resume.py::resume_pending_tool_approvals`
- **审批决定与恢复**：[FACT] `decide_tool_approval()` 只接受 approve/reject 和精确 `(tool_name, call_id)`；reject 必须带有界可读原因，approve 不接受多余原因。它从 v4 snapshot 重建带现有工作区 context 的 `RunState`，先恢复兼容模型的私有工具交换，再核对唯一 RUNNING Task 的 id/revision 和可用 previous response id，之后 CAS 保存 running、清除 snapshot，最后调用唯一 `Runner.resume_stream()`。恢复结果与 fresh 步骤共用 `_save_step_result()`，所以可再次等待审批、完成并继续，或 paused。`src/agents/chat_backend/planning_service.py::PlanningService.decide_tool_approval`、`_restore_approval_run`、`_resume_current_step`、`_save_step_result`
- **重试、修订与取消**：[FACT] `retry_current()` 只接受 paused，先把同一 journal CAS 保存为 running，再交回 `_drive_running()`；普通步骤不带旧 RunState fresh 重跑，final 只重跑固定验证。`revise()` 先把旧版未完成 Task 取消并置 superseded，创建继承安全快照的新版本 drafting，再直接复用 `draft()` 保存反馈和新草案。`cancel()` 取消未完成 Task、清空 snapshot 并让 Store 同事务恢复 default mode。三者都要求调用方 row revision。`src/agents/chat_backend/planning_service.py::PlanningService.retry_current`、`revise`、`cancel`、`src/agents/chat_backend/planning_store.py::_cancel_unfinished_tasks`
- **启动恢复**：[FACT] `recover_running(limit)` 接受 1..100 且 bool 不算 int；扫描时若严格解码报出可信 run id，先隔离再用剩余额度重扫。合法候选按 Store 顺序逐条 `_recover_one()`；成功离开 running 记 recovered，损坏记 isolated，临时错误保持原状态并记 deferred。报告只有计数和 UUID。`src/agents/chat_backend/planning_service.py::PlanningService.recover_running`、`_recover_one`、`PlanningRecoveryReport`
- **公共入口**：[FACT] `agents.chat_backend` 公开 `PlanningService`、`PlanningStepSnapshot/PlanningApprovalSnapshot/PlanningSnapshot/PlanningDraftOutcome/PlanningRecoveryReport/PlanningProgressEvent` 和 `PlanningInputError/PlanningRunError`；模块自己的 `__all__` 与子包转发保持一致。草案 schema、资源解析、Task 领取、串行循环和损坏隔离调用细节不单独导出，顶层 `agents` 也不复制这些 Chat Backend 名字。`src/agents/chat_backend/planning_service.py::__all__`、`src/agents/chat_backend/__init__.py::__all__`
